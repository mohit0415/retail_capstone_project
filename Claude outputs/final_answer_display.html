Final Answer — Display Guide

Four terminal shapes come out of POST /ask, discriminated by the status field. Each shows the raw JSON, a rendered card, and what your UI must display.

1. status: "answered" 200 OK

The happy path — validated, above confidence threshold, released by the Output Guardrail.

Raw JSON (AnswerResponse)

{
  "status": "answered",
  "request_id": "req_a17c...",
  "thread_id": "thr_92d1...",
  "answer": "ACME Corp must submit invoices within 30 days of goods delivery per §4.2 of the vendor management policy.",

      "version": "v3.1",
      "excerpt": "Invoices shall be submitted within 30 calendar days of delivery..."
    }
  ],
  "sql_evidence": null,
  "confidence": 0.87,
  "risk_level": "Low",
  "uncertainty_note": "",
  "evidence_path": "rag",
  "degraded": false,
  "timings": { "total_ms": 1897, "t4_ms": 1897 }

What the user sees

Confidence 87% Risk: Low rag
ACME Corp must submit invoices within 30 days of goods delivery per §4.2 of the vendor management policy.

Invoice Submission

Must display:
  • answer — the main text
  • Every citations[] entry as its own card — doc title, clause_number, section, version, excerpt (never collapse)
  • sql_evidence if not null (see NL2SQL variant below) — template_id, statement, row_count, as_of
  • confidence, risk_level, evidence_path as badges
  • uncertainty_note as a yellow callout if the string is non-empty
  • degraded: true → "Answered under budget pressure — some quality checks skipped"

Rendered under the answer

ACME Corp has 3 open audit findings as of 2025-12-31: two Medium severity and one High.
SQL Evidence · template: vendor_open_findings · 3 rows · as_of 2025-12-31

Rule: always show as_of next to any SQL-derived answer — a compliance answer without a pinned date is not reproducible. Show template_id so the caller can trace back which vetted query fired.

Entity resolution got 0 or many hits. No answer yet — ask the user to pick.

Raw JSON

  "status": "clarification_required",
  "request_id": "req_b23f...",
  "thread_id": "thr_e4a2...",
  "question": "Which ACME did you mean?",
  "candidates": [
    { "vendor_id": 1042, "vendor_name": "ACME Corp", "department": "Procurement" },
    { "vendor_id": 1108, "vendor_name": "ACME Logistics Ltd", "department": "Logistics" }
  ]
}

What the user sees

Needs clarification
Which ACME did you mean?
ACME Corp · Procurement id 1042
ACME Logistics Ltd · Logistics id 1108
Display rule: render each candidates[] row as a clickable option. When the user picks one, send the next /ask call with the same thread_id and the disambiguated query (e.g. "the one at id 1042") — the rewriter carries the choice forward.

4. status: "pending_review" 202 Accepted

Escalated to a human — no draft answer is returned (by design: showing the uncertified answer makes the review theatre).

Raw JSON

  "status": "pending_review",
  "request_id": "req_d5e2...",
  "thread_id": "thr_9b18...",
  "risk_level": "High",
  "reason": "confidence below threshold after reflection retries exhausted",
  "queued_at": "2026-09-05T12:31:04Z",
  "poll_url": "/requests/req_d5e2...",
  "timings": { "total_ms": 3812 }
}

What the user sees

Pending human review Risk: High
Sent to a compliance reviewer
Your question needs a reviewer's judgment before we can release an answer. We'll notify you when it's ready.
Reasonconfidence below threshold after reflection retries exhausted Queued at2026-09-05 12:31 UTC PollGET /requests/req_d5e2...

Critical rule (from architecture.md): never invent or show a draft answer here — the reason it escalated is that this answer could not be certified. Start polling poll_url; the reviewer's decision returns as a fresh AnswerResponse on the poll endpoint once the graph resumes.

5. Polling — GET /requests/{request_id}

Two terminal shapes come back once the reviewer decides:

Accepted or edited → same AnswerResponse

{
  "status": "answered",
  "answer": "...reviewer-approved text...",
  "citations": [ ... ],
  "confidence": 1.0,
  "evidence_path": "rag",
  // same fields as case 1
}

Rejected → still refused

{
  "status": "refused",
  "reason": "reviewer rejected: insufficient evidence"
}
Render the same UI cards as cases 1 and 3 — a human's answer passes the same PII scrub and citation check as a machine's, so its shape is identical.
